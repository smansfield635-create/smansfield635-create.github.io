# Methods Native Visual Architecture v1 — bounded checkpoints

Contract: `METHODS_NATIVE_VISUAL_ARCHITECTURE_REMEDIATION_PROTOTYPE_v1`

Authority boundary: protected nonproduct candidate only. Public Methods mutation, merge, deployment, and product acceptance are prohibited.

## Checkpoint 0 — baseline and custody

- Base: current `main` head at branch creation.
- Prior corrected adapter and instrument remain unchanged.
- Public Methods path is read-only input.
- Status: `PASS_CLOSED`.

## Checkpoint 1 — production-intent architecture

Required surfaces:

- one active model only;
- fixed, nonoverlapping Family, Model, Lens, Camera, and Coordinate regions;
- native `overview` and `browse` camera states;
- minimum 44×44 interaction targets;
- horizontal touch transition for X;
- complete 25-model JavaScript-disabled catalog;
- preserved inspection foreground and exact return.

Entry condition: Checkpoint 0 closed.
Exit condition: candidate route loads and native architecture contract is exposed.

## Checkpoint 2 — deterministic risk review

Five viewports: 360×800, 430×932, 768×1024, 1180×820, and 1440×1000.

Required checks:

- no horizontal overflow;
- all principal surfaces remain inside the viewport;
- no control/content overlap;
- exactly one visible active card;
- no neighboring-card competition;
- all controls at least 44×44;
- Overview and Browse are natively distinct;
- inspection returns to exact X/Y/Z/C state;
- touch X transition succeeds;
- reduced-motion frame is stable;
- static catalog contains all 25 models.

Exit dispositions:

- `PASS_WORTH_FULL_INSTRUMENT_VERIFICATION`
- `FAIL_REQUIRES_PROTOTYPE_REMEDIATION`

## Checkpoint 3 — bounded perceptual iteration

Run only if Checkpoint 2 returns a failure or a material visual concern. Modify the protected candidate, rerun the same risk set, and preserve each exact head and artifact.

## Checkpoint 4 — full instrument verification

Run the 1,575-primary evaluation instrument only after Checkpoint 2 is pass-closed and internal perceptual review finds the architecture materially coherent.

## Checkpoint 5 — user review and public transfer decision

The user reviews only an internally passing visual candidate. Public implementation requires a separate transfer operation and authority grant.

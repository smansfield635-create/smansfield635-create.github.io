## 3. Older external prior art — source/live and environment identity

The chronology does not rescue source-to-artifact provenance as a novelty claim.

### in-toto

in-toto predates Diamond Gate and provides signed layouts, authorized actors, step-by-step link metadata, material/product rules, and verification that the final software supply chain was executed as authorized and without tampering.

This occupies the general mechanism:

`authorized source/process -> signed evidence chain -> final artifact verification`

### SLSA provenance

SLSA provenance predates Diamond Gate and explicitly tracks build outputs back to source, records builder/invocation/materials/environment information, and supports consumer verification and rebuilding.

This occupies the general mechanism:

`source + build + environment -> verifiable artifact provenance`

Therefore:

`SOURCE_TO_ARTIFACT_IDENTITY_NOVELTY = REJECTED`

`EXECUTION_ENVIRONMENT_IDENTITY_NOVELTY = REJECTED`

`AUTHORIZED_BUILD/PROCESS_CHAIN_NOVELTY = REJECTED`

Diamond Gate may implement these differently and integrate them into a larger public system, but it cannot claim these low-level mechanisms as new.

## 4. What remains materially distinct

The surviving question is no longer provenance.

It is whether provenance/evidence state has authority over the public claim itself.

The target relation is:

`C_public(t) = Gamma(C, E_t, Q_t, P_t, A_t)`

where:

- `C` is the underlying claim;
- `E_t` is current admissible evidence;
- `Q_t` is qualification state;
- `P_t` is provenance / correspondence state;
- `A_t` is authority state;
- `Gamma` determines the strongest public representation presently authorized.

A mature implementation requires all of the following:

1. A claim has machine-readable standing.
2. Supporting evidence and qualification have machine-readable standing.
3. Source/live/public correspondence is checked rather than assumed.
4. Failure changes the claim state downward.
5. The public representation follows that downward state.
6. Recovery is not a manual label reset; it requires new admissible evidence / qualification.
7. The transition and recovery are receipt-bearing and externally inspectable.

## 6. Required next empirical closure

The chronological route is now sufficiently resolved to stop searching for novelty in generic provenance.

The next make-or-break boundary is executable:

1. Select one currently qualified public claim.
2. Bind its exact source, execution, evidence, qualification, and public representation identities.
3. Deliberately mutate the operative source or break reproduction while leaving presentation initially untouched.
4. Verify that the governing system detects correspondence failure.
5. Require `QUALIFIED -> HELD` (or equivalent) as a machine transition.
6. Verify that the served public representation contracts accordingly.
7. Restore the source/evidence.
8. Require fresh reproduction / qualification / receipts before public standing is restored.

If a human must manually decide to edit the webpage label, the strong BT4 claim is not demonstrated.

If the system forces the contraction and requires lawful evidence-bearing recovery, then Diamond Gate has demonstrated the exact higher-order relationship that remains unresolved by the chronological prior-art audit.

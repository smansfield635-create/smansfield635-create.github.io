Plane 01 · Identity

Agreement becomes an addressable unit.

ARCC / Overview

Domain role

ARCC identifies the Contract domain inside the four-asset ARCHCOIN architecture. It is the protocol unit associated with what is agreed, how the agreement is structured, and which obligations it carries.

Asset identity

Name: ARCHCOIN Contract. Symbol: ARCC. Standard: ERC-20 on the Ethereum EVM family, using 18 decimal places.

Present claim boundary

ARCC is implemented and locally qualified, but it is not represented here as a deployed cryptocurrency. No Sepolia contract address or on-chain deployment transaction exists yet.

Plane 02 · Construction

One mint at construction. No hidden lever afterward.

ARCC / Engineering

Implementation

ArchcoinFixedSupply.sol is written in Solidity 0.8.28 and extends OpenZeppelin Contracts 5.4.0 ERC20. The constructor receives the name, symbol, nonzero recipient, and positive supply.

Fixed-supply behavior

The constructor mints the entire supply once. The contract exposes no external mint function, public burn function, ownership module, role manager, pause switch, or privileged token-mutation path.

Qualification

Hardhat 2.28.0 with Toolbox 6.1.0 compiles and tests the shared implementation. ARCC deploys on the local EVM, preserves total supply, and completes a signed ERC-20 transfer.

Supply boundary

The local harness uses 1,000,000 units as a qualification fixture. That number is not a frozen Sepolia or mainnet issuance quantity, and no recipient wallet has been selected.

Plane 03 · Traversal

Qualified locally. Testnet is the next threshold.

ARCC / Platform

Current surface

The source, compiler configuration, automated tests, local deployment script, and signed-transaction qualification are present in the repository. ARCC shares one audited construction pattern with the other three assets.

Next network

The next deployment environment is Ethereum Sepolia, chain ID 11155111. It requires an owner-controlled wallet, funded Sepolia gas, a frozen supply quantity, and explicit deployment authorization.

Evidence after deployment

This plane advances only when the contract address, deployment transaction, retrievable bytecode, and ERC-20 behavior can be independently verified on-chain.

Mainnet remains later

Ethereum mainnet, chain ID 1, is not authorized. Mainnet follows successful testnet deployment and qualification; it is not implied by local success.

Plane 04 · Constraint

The boundary is part of the asset.

ARCC / Governance

Immutable token constraints

  • No post-deployment mint path.
  • No public burn in version one.
  • No privileged token mutation.
  • No mainnet deployment before testnet qualification.

Holder-rights boundary

One ARCC is a fungible Contract protocol unit only. It does not imply a legal, debt, equity, payment, redemption, governance, or ownership right.

Truthful public status

Constructed, compiled, tested, locally deployed, and transaction-qualified are supported claims. “Deployed cryptocurrency” remains prohibited until a verifiable network address and on-chain state exist.

01 / 04

Contract

  1. Input shape

    Practical
    The interface contract prevents confusion at the meeting point. It says what each side is allowed to send, receive, require, reject, and preserve. Name what crosses the interface.
    Engineering
    In engineering terms, the interface contract maps to schema, API contract, data type, event shape, method signature, precondition, postcondition, and version compatibility. Declare required and optional fields.
    Empirical
    For an interface contract requires recoverable definitions and observable enforcement. A contract that exists only in memory is not stable enough. Strong evidence: schema, tests, version history, validation failures, compatibility records.

  2. Output shape

    Practical
    The interface contract prevents confusion at the meeting point. It says what each side is allowed to send, receive, require, reject, and preserve. Name who owns the input and who owns the output.
    Engineering
    In engineering terms, the interface contract maps to schema, API contract, data type, event shape, method signature, precondition, postcondition, and version compatibility. Version the contract when meaning changes.
    Empirical
    For an interface contract requires recoverable definitions and observable enforcement. A contract that exists only in memory is not stable enough. Useful evidence: API docs, interface receipts, consumer compatibility notes.

  3. Obligation

    Practical
    The interface contract prevents confusion at the meeting point. It says what each side is allowed to send, receive, require, reject, and preserve. Define what counts as valid exchange.
    Engineering
    In engineering terms, the interface contract maps to schema, API contract, data type, event shape, method signature, precondition, postcondition, and version compatibility. Validate input before processing it.
    Empirical
    For an interface contract requires recoverable definitions and observable enforcement. A contract that exists only in memory is not stable enough. Failure mode: behavior depends on undocumented assumptions.

  4. Compatibility

    Practical
    The interface contract prevents confusion at the meeting point. It says what each side is allowed to send, receive, require, reject, and preserve. Reject silent compatibility assumptions.
    Engineering
    In engineering terms, the interface contract maps to schema, API contract, data type, event shape, method signature, precondition, postcondition, and version compatibility. Return explicit errors instead of ambiguous failure.
    Empirical
    For an interface contract requires recoverable definitions and observable enforcement. A contract that exists only in memory is not stable enough. Boundary: a contract is not proven just because both sides currently work once. Claim boundary: A contract is not proven just because both sides currently work once.

# EDUCATION SIX-CARD SINGLE-AUTHORITY RECONSTRUCTION CONTRACT v1

STATUS: FROZEN CONSTRUCTION AUTHORITY
SCOPE: Education six-card learner chamber
MODE: NON-DRIFT · NO PIECEMEAL CARD PATCHING

## Objective

Eliminate competing card authorities and close the six-card learner chamber as one coherent educational instrument.

Each card must have one canonical model controlling:
- id and construct;
- front and support;
- Learn explanation;
- Practice instruction;
- task;
- visual instrument;
- validation;
- retry;
- success evidence;
- evidence boundary;
- EN/ES/ZH learner-shell expression.

Carousel and expanded-card runtime must render from this authority.

EDUCATION_ARCHITECTURE may remain technical/program documentation but MUST NOT independently redefine learner-card semantics.

## Current crosswalk dispositions

### Possibility — RECONCILE
Current learner claim: bounded foundation provides reusable leverage and can support more than one message.
Current task: demonstrate both "I like music." and "I like dogs."
Defect: visual instrument still expresses the older "1,001 -> I am Sam." proof.
Required closure: front, explanation, instrument, task, validation and success must demonstrate one bounded-foundation leverage construct.
Boundary: no claim that 1,001 isolated words equal fluency or all English.

### Understanding — FREEZE / REFERENCE IMPLEMENTATION
Construct: a known word plus a productive pattern creates a changed lawful use.
Reference: play + -ed -> played.
Its learner-facing evidence chain is protected and should serve as the coherence model for other cards.

### Action — REDESIGN BOUNDED ASSEMBLY
Construct: learner actively assembles a simple English message from bounded components.
Required properties:
- meaningful correct and incorrect states;
- learner manipulates components rather than selecting a complete sentence;
- validation is deterministic and bounded;
- successful result visibly forms the sentence;
- retry teaches without becoming placement evidence.

PROHIBITED:
- unrestricted free-text production;
- all available options being correct;
- choosing among complete prebuilt sentences and calling that construction;
- any task requiring a general English-language grading engine.

### Progress — FREEZE LEARNER PATH / METADATA RECONCILE
Construct: attempt -> check -> feedback -> correction -> retry.
Current She walk. -> She walks. learner interaction is protected.
Only stale or mislabeled deep metadata may be reconciled.

### Independence — FREEZE LEARNER PATH / METADATA RECONCILE
Construct: support remains available while the learner attempts performance with less assistance.
Current show/hide-help learner behavior is protected.
Placement/demo-entry terminology must not act as learner-card semantic authority.

### Achievement — FREEZE CORE / EXPRESSION RECONCILE
Construct: transfer an earlier learned relationship to a changed surface.
Reference: Understanding teaches play -> played; Achievement applies the relationship to walk -> walked.
Core task and transfer distinction are protected.
Remaining story/localization language may be reconciled to this exact construct.

## Single-authority law

No card may derive learner semantics independently from multiple unsynchronized objects.

The successor model must provide one canonical semantic record per card. Existing HELP_LANGUAGES, PRODUCT_STORY, tasks, instrument(), validation/feedback code and deep metadata must either:
1. render from the canonical model;
2. become explicitly non-semantic presentation helpers; or
3. be retired from learner-card authority.

A change to a card construct must therefore propagate from one authority rather than requiring parallel hand edits.

## Evidence-chain acceptance

Every card must close:

CONSTRUCT
-> FRONT PROMISE
-> LEARN EXPLANATION
-> VISUAL INSTRUMENT
-> PRACTICE INSTRUCTION
-> LEARNER ACTION
-> CORRECT/INCORRECT STATE
-> FEEDBACK/RETRY
-> SUCCESS EVIDENCE
-> BOUNDARY

Any contradiction is a qualification failure.

## Distinct six-card evidence

Possibility: bounded-foundation leverage.
Understanding: productive pattern transformation.
Action: bounded component assembly.
Progress: feedback-driven correction.
Independence: reduced-support performance.
Achievement: changed-surface transfer.

No two cards may collapse to the same evidence claim.

## Localization parity

EN, ES and ZH may localize instructions, explanation and feedback.
Target-English exercise material remains English where required by the task.

All three help languages must express the same construct, success meaning and evidence boundary.

Stale Phase-1/demo-only language in learner-shell localization must be reconciled with:
- program-wide placement;
- D1-D7 + Capstone;
- four phases: Receive -> Place -> Use -> Own;
- Phase 1 public/free availability;
- later phases truthfully unavailable until developed/subscribed as applicable.

## Protected authorities

- CAPSTONE_BANK;
- placementCoordinate;
- adaptive placement thresholds/traversal;
- PROGRAM_PHASES mapping;
- curriculum availability/access truth;
- page-compression order;
- 3-6 month complete-program framing;

- client-local persistence truth.

## Physical acceptance

Qualification must exercise all six cards at phone, tablet and desktop widths.

For each:
1. bring card forward;
2. open;
3. inspect Understand face;
4. switch to Try It;
5. perform learner action;
6. exercise incorrect/retry path where the construct supports one;
7. achieve success;
8. verify success statement;
9. return to carousel.

Action specifically must prove:
- at least one invalid assembly is possible;
- at least one valid assembly is possible;
- no unrestricted text field exists;
- not all available choices/states pass;
- successful assembly visibly creates the intended sentence.

## Closure standard

Closure requires 6/6 coherent cards, EN/ES/ZH semantic parity, zero obsolete learner-card authorities, and no regression of placement/program/publication boundaries.

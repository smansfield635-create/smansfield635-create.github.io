## 1. Door / Explore precedent

The applicable precedent is not merely the final Door / Explore carousel appearance. It is the way the spatial system was constructed.

Door / Explore reached its integrated successor through separately closed animation families. The terminal publication record for commit `492b55572850a0f3160f664d23ec4e4bde8df3e7` records:

- 6 Door cards;
- 5 Explore cards;
- 11/11 card closure;
- 5/5 animation-family closure;
- separate family kernels / cycles before the final integrated surface was accepted.

The five recorded animation families were:

1. `Frontier` — Cycle 1;
2. `Products` — Cycle 2;
3. `InstrumentDecision` — Cycle 3;
4. `Laws` — Cycle 4;
5. `IdentityHome` — Cycle 5.

The important construction lesson is therefore:

```text
DO NOT DESIGN THE FINAL CAROUSEL AS ONE MONOLITHIC ANIMATION

DESIGN ONE SPATIAL OBJECT / LIFECYCLE
-> CLOSE IT
-> DESIGN THE NEXT
-> CLOSE IT
-> REPEAT
-> ONLY THEN COMPOSE THE CLOSED OBJECTS INTO THE SHARED CAROUSEL SYSTEM
```

The final carousel is the integration layer. It is not the place where the individual object identities are invented for the first time.

## 2. Awards successor construction law

The five Awards top-card living objects must follow the same staged method.

Each object is first treated as an independent spatial construction problem with its own:

- visual identity;
- three-dimensional depth model;
- lifecycle;
- signature motion;
- resting state;
- select response;
- reduced-motion equivalent;
- teardown / inactive behavior;
- current-source provenance;
- performance ceiling;
- mobile and tablet composition.

Only after that object is independently accepted may it become a member of the shared Awards carousel.

The construction sequence is therefore:

```text
CYCLE A — EXPERIENCE
CYCLE B — WORLD
CYCLE C — COHERENCE
CYCLE D — TRUST
CYCLE E — ESTATE
CYCLE F — SHARED CAROUSEL COMPOSITION
```

`CYCLE F` is forbidden from becoming a substitute for Cycles A-E.

## 3. Shared lifecycle grammar

The five objects may share a common lifecycle vocabulary, but they must not share an indistinguishable animation.

Recommended common state grammar:

```text
REAR_INERT
-> APPROACHING
-> FOREGROUND_REST
-> SIGNATURE_PLAY
-> FOREGROUND_IDLE
-> SELECT_RESPONSE
-> READER_OPEN
-> RETURN_RESTORING
-> FOREGROUND_REST
```

The lifecycle vocabulary is shared.

The visual event inside `SIGNATURE_PLAY`, the depth behavior, and the meaning of the object are card-specific.

The rear state remains lightweight and inert. Only the foreground card may own heavyweight runtime where required.

## 4. Cycle A — EXPERIENCE

Claim:

`A website can behave like a place.`

Construction target:

A spatial orientation object derived from the current Compass / current estate navigation grammar, not a generic compass icon and not a retired Awards donor.

The object must communicate place, orientation and relation before explanatory copy is opened.

Independent closure requires:

- recognizably current Diamond Gate spatial language;
- genuine depth rather than a flat symbol moving on a card;
- a meaningful approach-to-center transition;
- a signature orientation / relation event;
- stable foreground resting pose;
- reduced-motion equivalent;
- mobile, tablet and desktop legibility;
- no dependence on the final five-card orbit to make the object intelligible.

## 5. Cycle B — WORLD

Claim:

`The browser was not the window. It became the world.`

Construction target:

A current browser-native world object or bounded live representation of H-Earth / current world construction.

The object must communicate that the environment is being executed as a world, not shown as a screenshot, poster or generic globe decoration.

Independent closure requires:

- current world provenance;
- volumetric / spatial reading;
- a signature world-reveal or world-state event;
- explicit performance and memory ceiling;
- foreground-only heavyweight runtime where a real renderer is used;
- lightweight rear representation;
- reduced-motion equivalent;
- no use of retired Brain imagery as a proxy for world construction.

## 6. Cycle C — COHERENCE

Claim:

`Coherence moved from idea to instrument.`

Construction target:

A spatial diagnostic object based on the current Coheriscope / Coherence Index / score interaction.

The signature animation should communicate movement from input / relationships toward an inspectable result. It should not reduce the concept to a decorative brain, abstract graph or generic gauge.

Independent closure requires:

- direct recognizability of the current diagnostic language;
- relationship-to-result motion;
- inspectable index / score cue without pretending the card itself is the full diagnostic;
- clear depth hierarchy;
- reduced-motion equivalent;
- claim boundaries preserved;
- no scientific or clinical certification implication.

## 7. Cycle D — TRUST

Claim:

`Software should have to earn the right to say it worked.`

Construction target:

A spatial governance / evidence object that makes authority progression visible.

The signature event should show a bounded progression such as:

```text
INTENT
-> EXECUTION
-> VERIFICATION
-> EVIDENCE
-> AUTHORIZED CLAIM
```

with HOLD / DENY / FAIL-CLOSED semantics available where appropriate.

This must not become a generic five-node flowchart floating in 3D. The depth and motion must make the difference between execution and earned authority perceptible.

Independent closure requires:

- current Governance / Evidence provenance;
- spatial differentiation of stages or authority boundaries;
- signature admission / hold / claim event;
- stable final authorized state;
- reduced-motion equivalent;
- no implication that every execution is successful;
- no use of PR #1000 as the object identity.

## 8. Cycle E — ESTATE

Claim:

`The surprise is not one feature. It is that the pieces belong together.`

Construction target:

A spatial estate object showing multiple current Diamond Gate surfaces resolving into one coherent place.

This is the closest Awards analogue to Door / Explore's mature multi-object identity work, but it must use current estate objects and current relationships rather than inherit a legacy orbital diagram.

Independent closure requires:

- multiple recognizable current estate elements;
- visible relation / belonging rather than a pile of icons;
- a signature convergence or constellation event;
- clear foreground depth;
- lightweight resting state;
- reduced-motion equivalent;
- no false implication that all subsystems have identical maturity or authority.

## 9. Cycle F — shared carousel composition

Only after Cycles A-E are independently closed may the five living objects be integrated into the Awards top carousel.

Composition work is limited to shared-system behavior:

- spatial card placement;
- foreground / rear depth law;
- swipe and drag traversal;
- rear-card tap to front;
- active-card tap to `SELECT_RESPONSE` then reader;
- exact return to origin hash, focus and resting pose;
- one-heavy-runtime ceiling;
- inactive teardown;
- shared responsive geometry;
- cross-card transition pacing;
- keyboard traversal;
- reduced-motion system behavior.

Composition must not materially redesign a closed object merely to make the carousel easier to implement. If integration exposes a true conflict, reopen only the affected object's bounded construction cycle rather than flattening every object into a common generic animation.


## 11. Prohibited shortcut

The following successor pattern is explicitly rejected:

```text
BUILD GENERIC FIVE-CARD CAROUSEL
-> INSERT FIVE DIFFERENT ICONS / DIAGRAMS
-> APPLY ONE COMMON ANIMATION
-> CALL THE RESULT FIVE LIVING OBJECTS
```

That would reproduce the visual sameness the Door / Explore construction process avoided.

The accepted pattern is:

```text
FIVE DISTINCT SPATIAL EXPERIENCES
-> FIVE CLOSED LIFECYCLES
-> ONE SHARED COMPOSITION SYSTEM
```

This construction law is subordinate to the content and award-lane authority in `AWARDS_TWO_CAROUSEL_CROSSWALK_20260911.md` and governs how the five top-card living proofs are to be built.

# LAWS CAROUSEL REFERENCE-PORT MASTER STRATEGY v1

Status: FROZEN CONSTRUCTION AUTHORITY
Date: 2026-08-16
Scope: Laws destination carousel only
Reference implementation: `laws/research/methods-and-models/`

## 1. Governing decision

The Methods & Models carousel is the normative functioning spatial reference for the Laws carousel repair.

The Laws carousel MUST NOT continue as an independently evolving carousel engine. Laws contributes context, information architecture, content, destination semantics, visual language, stage placement, and page integration. Methods & Models contributes carousel geometry, gesture custody, spatial state, settlement, seam behavior, and shared-orbit interaction architecture.

Canonical equation:

`METHODS WORKING SPATIAL KERNEL + LAWS CONTENT/PRESENTATION = REPAIRED LAWS CAROUSEL`

The current v8 Laws spatial architecture is not repair authority. It may be mined only for Laws-specific contextual requirements that are not already supplied by the Methods reference.

## 2. Non-negotiable inheritance boundary

### Preserve from Laws
- all destination content and destination identities;
- all intended information grouping/family architecture;
- stage placement below the Compass;
- Laws visual language and hierarchy;
- destination meaning, links/actions, and evidence/content authority;
- required accessibility relationships;
- responsive page integration and vertical document traversal;
- contextual family switching where required;
- Return to Orbit language and object continuity where applicable.

### Inherit from Methods & Models
- one shared Euclidean orbit/ring;
- one authoritative spatial coordinate;
- direct pointer manipulation of that same spatial coordinate;
- drag-time transition suppression;
- release/snap of the same spatial object;
- normalized circular index behavior;
- one shared selection primitive for tabs/keyboard/card selection;
- exclusion of inspection while spatial settlement is active;
- reduced-motion treatment;
- spatial continuity through inspection/return.

### Presumed non-authoritative legacy
Any existing Laws carousel mechanism not required by the Laws-preservation list above is presumed removable. It must not survive merely because it already exists.

## 3. Accounted deficiencies and binding remedies

### D01 — Architectural drift
Laws diverged from the proven Methods carousel and became a separate engine.

Remedy: replace the Laws spatial kernel with a direct adaptation of the Methods kernel.

### D02 — Legacy Laws contamination
Pre-carousel Laws interaction concepts were carried into the new carousel beyond contextual necessity.

Remedy: retain only Laws context/content/page responsibilities. Remove inherited mechanics that duplicate or compete with the reference kernel.

### D03 — Multiple spatial authorities
Current Laws uses per-card geometry plus orbit/detent/target state and settlement reconstruction.

Remedy: one ring is the spatial object. Cards occupy fixed structural positions on the ring. Only the ring coordinate rotates.

### D04 — Reinvented gesture law
The direction-only/atomic-step law replaced the proven Methods direct-manipulation model.

Remedy: pointer movement directly manipulates the shared orbit coordinate as in Methods. Do not invent a different gesture model unless the reference itself is separately found defective.

### D05 — Settlement discontinuity
Gesture custody and settlement became separate geometry systems.

Remedy: the same spatial coordinate used during drag MUST be the coordinate that snaps/settles after release.

### D06 — Excess state-machine complexity
Laws accumulated pending/direction-locked/detent/target/transaction/canonical-guard machinery largely to control conflicts created by the derivative architecture.

Remedy: collapse toward the Methods state grammar. Additional state requires an explicit Laws-specific justification.

### D07 — Spatial/semantic divergence
Visible geometry and semantic selection could represent different effective states during movement/settlement.

Remedy: one normalized selected index and one orbit coordinate. Semantic commitment occurs at the defined reference snap/selection boundary.

### D08 — Circular seam ambiguity
Unwrapped detent identities created ambiguity such as `-1` versus `count-1`.

Remedy: use normalized circular indices and reference ring angles. Seam traversal is ordinary orbit traversal.

### D09 — Competing interaction ownership
Pointer, focus, click, keyboard, restore, and tabs gained independent repositioning pathways.

Remedy: all non-pointer selection pathways route through one shared selection primitive. No pathway computes independent geometry.

### D10 — Stage/carousel coupling
Destination-stage logic became entangled with carousel geometry and state restoration.

Remedy: stage authority selects/mounts Laws content family; carousel authority controls spatial position within that family. Stage code never owns carousel geometry.

### D11 — Content-integrity risk during rebuild
A reference port could accidentally flatten or alter Laws information architecture.

Remedy: freeze an inventory of destination records, family membership, labels, actions, and required content before spatial replacement. Post-port content must match this inventory.

### D12 — Visual-language contamination risk
Porting Methods mechanics could accidentally transplant Methods styling.

Remedy: port mechanics, not page styling. Laws remains the restrained continuation below the Compass. The Compass remains the dominant spectacle.

### D13 — Synthetic qualification certified implementation rather than experience
Tests asserted derivative telemetry and could pass without proving reference-equivalent behavior.

Remedy: qualification must test observable/reference invariants first. Implementation telemetry is secondary evidence only.

### D14 — Physical-device evidence was not controlling enough
Synthetic browser PASS was allowed to close a touch-driven interaction cycle despite contradictory tablet behavior.

Remedy: physical phone/tablet touch confirmation is a mandatory merge gate for carousel-architecture changes.

### D15 — Executed runtime identity was not observable
When physical behavior contradicted expected behavior, the running code version could not be proven from the device evidence.

Remedy: expose deterministic runtime/build identity through a nonintrusive diagnostic surface and record it during physical qualification.

### D16 — Cache/deployment ambiguity
Merged source identity did not by itself prove served or executed identity.

Remedy: every candidate uses a unique immutable asset/build identity. Qualification records source, served, and executed identity before classifying behavior.

### D17 — Stale instrumentation
Legacy verifiers continued to enforce superseded carousel assumptions.

Remedy: classify every carousel-related verifier before construction as `REFERENCE_VALID`, `LAWS_CONTEXT_VALID`, `REWRITE_REQUIRED`, or `SUPERSEDED`. Superseded checks cannot certify or block the successor.

### D18 — Audit implementation bias
Tests became coupled to detents, transaction IDs, and derivative internals rather than user-visible spatial law.

Remedy: primary audit assertions are architectural/observable: shared orbit, direct manipulation, coherent snap, seam continuity, no second movement, vertical scroll availability, correct content identity, inspection continuity, and final canonical geometry.

### D19 — Construction-cycle truncation
Audit failures were treated as stopping/reporting points rather than inputs to continued construction.

Remedy: a construction cycle remains open through `CONSTRUCT -> AUDIT -> DEFICIENCY -> REPAIR -> RE-AUDIT` until qualified and merged or until a genuinely terminal blocker is established.

### D20 — Future reference drift
Even a successful Laws port could later diverge through independent carousel modifications.

Remedy: this document and the Methods reference become normative carousel authority. Future spatial-mechanics changes require an explicit standard change, not page-local invention.

## 4. Target spatial architecture

The target Laws carousel MUST reduce to this ownership chain:

`POINTER -> SHARED ORBIT COORDINATE -> SHARED RING TRANSFORM -> SNAP -> NORMALIZED INDEX`

Required properties:
1. one shared ring/orbit object;
2. one authoritative continuous spatial coordinate;
3. cards are structurally attached to the ring rather than independently animated through competing coordinates;
4. pointer movement directly changes the shared coordinate;
5. drag disables settlement transition/interpolation on the shared ring;
6. release resolves and snaps that same coordinate;
7. tabs, keyboard, and card selection call one selection primitive;
8. circular traversal normalizes index identity;
9. vertical touch traversal remains available to the document;
10. inspection/open state cannot create a second spatial authority;
11. return restores the same object/orbit relationship;
12. reduced motion preserves deterministic final state.

## 5. Explicit prohibitions

Construction MUST NOT:
- repair or extend the v8 detent/target/transaction architecture as the successor spatial model;
- preserve legacy Laws mechanics merely because they are already wired into the page;
- create independent per-card settlement authority when the reference uses a shared ring;
- invent a new gesture law while the Methods reference remains functioning;
- let stage/family logic calculate spatial geometry;
- let focus, click, keyboard, restore, or tabs own separate geometry paths;
- certify the candidate solely through synthetic browser tests;
- merge while executed runtime identity is unresolved;
- merge while physical-device behavior contradicts the reference;
- weaken Laws content or information architecture to simplify the port;
- transplant Methods visual styling wholesale into Laws.

### Phase II — Freeze Laws context
Inventory and freeze:

- family membership/order;
- visible labels/headings/questions;
- links/actions;
- destination-stage structure;
- accessibility requirements;

### Phase III — Replace spatial kernel
Remove current Laws spatial authority from the carousel path and install a Laws-adapted Methods ring kernel.

The first candidate should prove only:
- Laws records occupy the shared ring;
- pointer direct manipulation works;
- release snap works;
- normalized index and seam work;
- no duplicate geometry authority remains.

### Phase IV — Reconnect context incrementally
Reconnect, one bounded responsibility at a time:
1. family/stage selection;
2. destination activation;
3. tabs;
4. keyboard;
5. card selection;
6. inspection/open behavior;
7. Return to Orbit;
8. responsive/mobile integration;
9. vertical scroll custody;
10. accessibility relationships;
11. any justified state restoration.

Each reconnect must use the shared orbit API and may not create geometry authority.

### Phase V — Comparative qualification
Run homologous interaction vectors against Methods and Laws.

Compare:
- initial canonical frame;
- direct drag response;
- directionality;
- short/long drag behavior;
- release snap;
- repeated traversal;
- reverse traversal;
- circular seam;
- vertical page traversal;
- keyboard selection;
- tab/card selection;
- inspection/return continuity;
- reduced motion;
- final centered/canonical state;
- absence of post-landing second movement.

Laws need not be visually identical to Methods. Its spatial behavior must be reference-equivalent unless a documented Laws contextual requirement requires a bounded deviation.

### Phase VI — Physical qualification and merge
Before merge:
- record exact source commit;
- record unique asset/build identity;
- prove browser loaded that identity;
- prove physical device executed that identity;
- perform real touch traversal on phone/tablet;
- compare behavior with the Methods reference;
- record any discrepancy as a deficiency;
- repair and rerun the complete affected audit set.

Merge only after all controlling gates pass.

## 7. Verifier classification law

Every existing carousel/Laws verifier must receive one status before it can participate in qualification:

- `REFERENCE_VALID`: proves a spatial invariant shared with Methods.
- `LAWS_CONTEXT_VALID`: proves preserved Laws content/page/context behavior without asserting obsolete spatial mechanics.
- `REWRITE_REQUIRED`: contains useful intent but encodes superseded implementation assumptions.
- `SUPERSEDED`: no longer applicable and cannot block or certify the successor.

A failing `SUPERSEDED` verifier is informational only. A passing `SUPERSEDED` verifier is also informational only.

## 11. Construction-cycle law

The cycle is not complete at the first audit.

`REFERENCE -> CONSTRUCT -> AUDIT -> DEFICIENCY -> REPAIR -> RE-AUDIT -> ... -> QUALIFIED -> MERGE`

If an audit discovers a material failure, the failure is pinned to this strategy, repaired inside the same construction cycle, and the affected qualification set is rerun. The cycle ends only at merge or a documented genuinely terminal blocker.

## 12. Deviation rule

Any intentional departure from Methods spatial behavior requires, before implementation:
1. the exact reference behavior;
2. the Laws-specific contextual requirement that cannot be satisfied by the reference behavior;
3. the smallest proposed deviation;
4. its new deterministic invariant;
5. its qualification method;
6. explicit admission into this strategy.

Undocumented spatial deviation is a defect.

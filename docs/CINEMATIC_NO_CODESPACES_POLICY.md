# Cinematic Execution Substrate Policy — No Codespaces

Status: **OWNER-DIRECTED CONTROLLING PRODUCTION POLICY**  
Date: 2026-09-05

## Owner directive

For **all cinematic, film, video, page-intro, orientation-film, Chapter, About, Compass, and successor cinematic work moving forward**:

> **DO NOT USE CODESPACES.**

This is a hard production constraint, not a preference and not a fallback-order suggestion.

## Scope

This prohibition applies to cinematic work at every stage, including:

- precedent review;
- source binding;
- branch construction;
- cinematic rendering or reconstruction;
- verification and focused smoke checks;
- router or classification support;
- recovery from a stalled room;
- qualification;
- owner-review preparation;
- publication preparation.

A room must not create, request, recommend, require, wait for, or route cinematic work through a GitHub Codespace.

## Precedence over generic execution-substrate suggestions

Repository-level generic execution policies may list Codespaces or disposable builders as possible execution substrates for other classes of work. That generic availability **does not create a Codespaces requirement for cinematic work** and must not be used to escalate a bounded cinematic task into an infrastructure task.

For cinematic work, the production path is determined first by the actual cinematic scope and established cinematic precedent.

When the task remains a bounded, non-authoritative cinematic/presentation operation, use the established direct production pattern:

`PRECEDENT / SOURCE TRUTH -> BOUNDED BRANCH CONSTRUCTION -> PROPORTIONAL VERIFICATION -> OWNER INSPECTION / REVERSIBLE PUBLICATION WHEN AUTHORIZED`

Do not substitute:

`MISSING LOCAL COMMAND -> CODESPACE -> NEW EXECUTION ENVIRONMENT`

for that production path.

## Established cinematic precedent

The controlling precedent family includes:

- About cinematic branch construction and correction through PR #2593;
- Compass bounded publication/live-inspection precedent in PR #2684;
- noninteractive cinematic proportional qualification in PR #2697;
- `BOUNDED_PAGE_RELEASE` cinematic adoption precedent in PR #2717 and its successor repairs.

The recurring lesson is that bounded cinematic work is not to be converted into a general-purpose execution-environment project merely because a preferred local command or exhaustive browser matrix is unavailable.

## Allowed production methods

Cinematic work may proceed through the smallest lawful non-Codespaces method already available for the task, including:

- direct bounded branch construction using connected GitHub/native repository tools;
- source-level and exact-diff verification;
- existing focused browser/render evidence when already available;
- owner-supplied video review;
- reversible live owner inspection when separately authorized;
- rollback/unhook if rejected.

This policy does **not** authorize GitHub Actions as agent-execution transport and does not bypass any genuinely applicable runtime, navigation, controller, shared-state, analytics, governance, or publication authority.

## Stop rule

If a cinematic room concludes that progress requires Codespaces, it must **stop before creating or requesting one** and re-evaluate the task against this policy and the cinematic precedent.

The only way this prohibition may be superseded is by a later explicit owner instruction that specifically authorizes Codespaces for a named cinematic operation.

Silence, generic repository policy, unavailable local shell execution, missing router command execution, or a desire for broader verification do not supersede this rule.

## Recovery rule for future rooms

Any fresh room handling cinematic work must treat the following as controlling:

`CINEMATIC_CODESPACES = PROHIBITED`

`GENERIC_CODESPACE_FALLBACK = NOT_APPLICABLE`

`MISSING_NATIVE_COMMAND != REQUIREMENT_TO_CREATE_CODESPACE`

`BOUNDED_CINEMATIC_WORK = KEEP_ON_THE_ESTABLISHED_DIRECT_PRODUCTION_PATH`

If a prior room drifted toward Codespaces, recover from the last durable cinematic checkpoint and continue from the first unresolved cinematic boundary. Do not inherit the Codespaces detour.

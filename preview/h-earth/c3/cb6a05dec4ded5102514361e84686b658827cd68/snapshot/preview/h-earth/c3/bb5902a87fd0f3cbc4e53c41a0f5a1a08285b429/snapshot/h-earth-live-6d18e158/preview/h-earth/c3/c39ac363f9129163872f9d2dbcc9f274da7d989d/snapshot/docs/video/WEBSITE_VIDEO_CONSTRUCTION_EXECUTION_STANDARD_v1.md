# WEBSITE_VIDEO_CONSTRUCTION_EXECUTION_STANDARD_v1

Status: GOVERNING CONSTRUCTION PROCEDURE
Scope: Diamond Gate Bridge cinematic website films
Entry authority: AI entry point

## Purpose
Prevent repeated recovery loops, premature compatibility assurances, and inspection of artifacts whose presentation geometry has not been qualified.

## Governing separation
Every film has four separately governed layers:
1. SOURCE PIXELS — canonical high-resolution footage.
2. EDITORIAL AUTHORITY — shot order, timing, narrative cadence, transitions, reading windows.
3. PRESENTATION GEOMETRY — native website aspect ratio and shot-specific composition.
4. FINISH — typography, narration/music, mastering.

A pass in one layer never implies a pass in another.

## Mandatory preflight before construction
Construction may not be announced as executable until all are true:
- canonical source binary is physically mounted/readable;
- source identity is recorded by filename, byte size, duration, dimensions, codec/fps, SHA-256 when available;
- editorial authority is frozen and retrievable;
- target live presentation contract is frozen;
- every shot has a lawful geometry treatment;
- required local executables are present;
- output and inspection surfaces are available.

`SPECIFICATION_READY` without `SOURCE_BINARY_AVAILABLE` is not `RENDERABLE`.

## Deterministic construction sequence
### C0 — Recover and verify source
Acquire the canonical binary through the AI entry point / authorized storage connector. Mount it locally. Probe it directly. Do not substitute an editorial proxy.

### C1 — Freeze editorial authority
Record shot order, source intervals, output intervals, durations, transition intent, reading windows, and repair decisions. Preserve hashes of existing editorial masters. Do not silently overwrite prior candidates.

### C2 — Freeze live presentation contract
For current Awards films: native 1920x1080 16:9 master. Portrait capture is source material, never final presentation geometry. Prohibited: whole-phone-in-black-field, universal crop, browser-shell framing, stretch-to-fill, black-bar substitute, or unqualified blurred-copy surround.

### C3 — Build shot recomposition map
Every shot must be classified before rendering as `REFRAME`, `PAN_SCAN`, or `COMPOSITE`. Each record specifies protected subject, permitted crop, motion path where required, and acceptance condition. No shot may enter render with an undefined geometry treatment.

### C4 — Pixel construction
Decode the canonical source and construct each shot independently into the native landscape field. Preserve editorial timing. Use shot-specific geometry; never apply one universal crop recipe. Render picture only.

### C5 — Picture qualification
Before text/music, verify:
- exact target duration;
- 1920x1080 native landscape output;
- expected frame rate/codec;
- all editorial shots present in order;
- no device-like floating portrait presentation;
- no accidental black-band composition;
- no browser chrome dominance;
- protected subjects remain legible;
- known motion defects repaired;
- decode passes;
- representative frames satisfy the live presentation contract.

Only `PICTURE_LIVE_COMPATIBILITY_PASS` admits finishing.

### C6 — Typography and comprehension pass
Opening law: dedicated dark cinematic canvas -> first statement alone -> readable hold -> statement clears -> first moving visual reveal.

Thereafter use the comprehension traversal:
`READ -> LOOK -> TRANSITION -> READ -> LOOK`.

Text appears only in prepared low-demand windows. Long semantic statements may be split. Important moving imagery and important reading may not compete simultaneously.

### C7 — Music/audio pass
Add soundtrack only after picture compatibility and text timing are stable. Audio must support, not dictate, editorial timing. Recheck text intelligibility and transition emphasis after mix.

### C8 — Final qualification
Verify container, codec, dimensions, frame rate, duration, audio, decode, phone-safe text, live geometry equivalence, narrative order, and no regression to device framing. Compare representative frames against successful existing live films.

Only `FINAL_WEBSITE_FILM_PASS` may enter owner live-review consideration.

### C9 — Isolated inspection before production
Materialize the exact qualified candidate on an isolated browser inspection surface. Owner inspects the actual presentation candidate. Production replacement is a separate authority boundary.

## Failure behavior
Recoverable construction defects remain inside the active cycle:
`FAIL -> NAMED DEFECT -> REPAIR -> REQUALIFY`.

Do not return routine internal defects as owner blockers. Return only an inspection-ready artifact or a genuinely non-resolvable owner-decision boundary.

## Artifact lineage
Every project must preserve:
`SOURCE -> EDITORIAL AUTHORITY -> PICTURE MASTER -> FINISHED MASTER -> LIVE CANDIDATE`.

Each stage records identity and status. Rejected candidates remain retrievable evidence and are never silently promoted.

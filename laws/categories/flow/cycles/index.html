Recurrence

  1. Return pattern

    Practical
    Recurrence is the first sign that an event may not be isolated. It asks whether the same kind of signal is returning often enough to deserve cycle reading. Name what returned.
    Engineering
    Recurrence becomes measurable when event type, timing, interval, amplitude, state change, and prior-pass comparison are recorded consistently. Record event timestamp and type.
    Empirical
    For recurrence requires more than memory. It needs records showing that the signal returned under comparable conditions. Strong evidence: timestamped event records, repeated signal class, interval history, comparable state notes.

  2. Interval

    Practical
    Recurrence is the first sign that an event may not be isolated. It asks whether the same kind of signal is returning often enough to deserve cycle reading. Compare this pass to the last pass.
    Engineering
    Recurrence becomes measurable when event type, timing, interval, amplitude, state change, and prior-pass comparison are recorded consistently. Compare interval between passes.
    Empirical
    For recurrence requires more than memory. It needs records showing that the signal returned under comparable conditions. Useful evidence: sequence logs, news/event archives, pattern review notes, pass-by-pass summaries.

  3. State comparison

    Practical
    Recurrence is the first sign that an event may not be isolated. It asks whether the same kind of signal is returning often enough to deserve cycle reading. Separate coincidence from meaningful recurrence.
    Engineering
    Recurrence becomes measurable when event type, timing, interval, amplitude, state change, and prior-pass comparison are recorded consistently. Track amplitude or intensity where available.
    Empirical
    For recurrence requires more than memory. It needs records showing that the signal returned under comparable conditions. Failure mode: one dramatic event is treated as a cycle without recurrence.

  4. Repeat signal

    Practical
    Recurrence is the first sign that an event may not be isolated. It asks whether the same kind of signal is returning often enough to deserve cycle reading. Track whether the return arrives with more pressure, less pressure, or the same pressure.

    Empirical

Rhythm

  1. Cadence

    Practical
    Rhythm is the timing signature of a cycle. It shows whether the return is random, spaced, accelerating, compressing, delayed, or entering a recognizable cadence. Ask when the return happens.
    Engineering
    Rhythm maps to interval analysis, phase tracking, cadence classification, compression ratio, expansion ratio, and timing-window comparison. Calculate interval between recorded passes.
    Empirical
    For rhythm requires enough timestamped passes to distinguish cadence from coincidence. Strong evidence: multiple timestamped passes, interval table, phase notes, compression/expansion record.

  2. Phase

    Practical
    Rhythm is the timing signature of a cycle. It shows whether the return is random, spaced, accelerating, compressing, delayed, or entering a recognizable cadence. Compare the timing gap between returns.
    Engineering
    Rhythm maps to interval analysis, phase tracking, cadence classification, compression ratio, expansion ratio, and timing-window comparison. Compare current interval to previous interval.
    Empirical
    For rhythm requires enough timestamped passes to distinguish cadence from coincidence. Useful evidence: cadence charts, sequence summaries, event windows, timing deltas.

  3. Timing gap

    Practical
    Rhythm is the timing signature of a cycle. It shows whether the return is random, spaced, accelerating, compressing, delayed, or entering a recognizable cadence. Watch for compression or delay.
    Engineering
    Rhythm maps to interval analysis, phase tracking, cadence classification, compression ratio, expansion ratio, and timing-window comparison. Classify cadence as stable, compressing, expanding, irregular, or broken.
    Empirical
    For rhythm requires enough timestamped passes to distinguish cadence from coincidence. Failure mode: rhythm is inferred from too few returns.

  4. Compression

    Practical
    Rhythm is the timing signature of a cycle. It shows whether the return is random, spaced, accelerating, compressing, delayed, or entering a recognizable cadence. Do not call a rhythm stable until enough passes are visible.
    Engineering
    Rhythm maps to interval analysis, phase tracking, cadence classification, compression ratio, expansion ratio, and timing-window comparison. Track whether timing aligns with a declared sequence lens.
    Empirical
    For rhythm requires enough timestamped passes to distinguish cadence from coincidence. Boundary: rhythm is timing structure, not proof of cause by itself. Claim boundary: Rhythm is timing structure, not proof of cause by itself.

Feedback

  1. Output return

    Practical
    Feedback is what the cycle carries back into itself. A return is not neutral if the last pass changed the next pass. Ask what changed after the last return.
    Engineering
    Feedback maps to state transition, amplification, damping, recurrence pressure, output-to-input return, and system memory across passes. Track previous output as new input.
    Empirical
    For feedback requires a trace showing that one pass affected the next pass. Strong evidence: before/after state records, output-input trace, amplification/damping record, causal timing window.

  2. Amplification

    Practical
    Feedback is what the cycle carries back into itself. A return is not neutral if the last pass changed the next pass. Track whether the cycle got stronger or weaker.
    Engineering
    Feedback maps to state transition, amplification, damping, recurrence pressure, output-to-input return, and system memory across passes. Measure amplification or damping across passes.
    Empirical
    For feedback requires a trace showing that one pass affected the next pass. Useful evidence: recurrence pressure logs, state comparison, sequence notes, feedback review.

  3. Damping

    Practical
    Feedback is what the cycle carries back into itself. A return is not neutral if the last pass changed the next pass. Watch for self-reinforcing pressure.
    Engineering
    Feedback maps to state transition, amplification, damping, recurrence pressure, output-to-input return, and system memory across passes. Record whether feedback changes interval, amplitude, or phase.
    Empirical
    For feedback requires a trace showing that one pass affected the next pass. Failure mode: repeated events are called feedback without showing return influence.

  4. State change

    Practical
    Feedback is what the cycle carries back into itself. A return is not neutral if the last pass changed the next pass. Distinguish healing feedback from collapse feedback.
    Engineering
    Feedback maps to state transition, amplification, damping, recurrence pressure, output-to-input return, and system memory across passes. Classify feedback as stabilizing, escalating, neutral, or degrading.
    Empirical
    For feedback requires a trace showing that one pass affected the next pass. Boundary: feedback requires connection, not just repetition. Claim boundary: Feedback requires connection, not just repetition.

Renewal

  1. Return with repair

    Practical
    Renewal is the difference between a cycle that traps the system and a cycle that restores it. Renewal asks whether the return creates repair, readiness, learning, or a better next pass. Does the cycle return with less damage?
    Engineering
    Renewal maps to post-cycle repair, state reset, retained learning, closure quality, residual load reduction, and readiness for the next pass. Compare residual load before and after closure.
    Empirical
    For renewal requires proof that the cycle changed the next cycle’s starting condition. Strong evidence: repair record, closure record, next-pass improvement, residual-load comparison.

  2. Regeneration

    Empirical

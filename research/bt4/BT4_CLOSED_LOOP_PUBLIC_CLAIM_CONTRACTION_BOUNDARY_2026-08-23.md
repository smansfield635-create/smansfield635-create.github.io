# BT4 Closed-Loop Public Claim Contraction Boundary — 2026-08-23

Status: `BT4_CLOSED_LOOP_BOUNDARY_EXECUTED_v1`

Purpose: test the strongest surviving BT4 proposition against the current Diamond Gate public claim system without manufacturing a new mechanism and then mistaking the new mechanism for evidence that the old system already possessed it.

## Hypothesis under test

The surviving proposition is stronger than provenance, claim/evidence linkage, workflow gating, or manually maintained claim boundaries.

Required closed loop:

`EVIDENCE / QUALIFICATION / PROVENANCE FAILURE -> MACHINE EPISTEMIC DOWNGRADE -> MANDATORY PUBLIC CLAIM CONTRACTION -> EVIDENCE-BEARING REQUALIFICATION BEFORE RESTORATION`

A system passes only if degradation of a bound supporting condition itself compels the public claim state to contract. A human editing a claim after noticing a problem is evidence of disciplined governance, but it is not the claimed automated closed loop.

## Automatic closed-loop audit

The test then asked whether the contraction was produced by an executable claim-entitlement consumer.

Repository search was performed for consumers of:

- `assets/credibility/claims.v1.json`;
- `highestProofLevel`;
- `claimsNotYetAuthorized`;
- `ACTIVE_PUBLIC_EVIDENCE_REGISTRY`;
- public credibility claim registry semantics.

The searchable results locate the claim registry itself and copies embedded in generated/snapshot surfaces. No first-class executable consumer was located that:

1. recomputes claim standing from current evidence identities or qualification receipts;
2. detects loss/mutation of a bound evidence object;
3. changes `status`, `proofState`, domain placement, or public wording as a necessary consequence;
4. blocks a stale stronger public representation from being served;
5. requires a new admissible receipt/qualification event before restoration.

The `assets/credibility/` public surface currently contains the registry and related benchmark/presentation assets, but no located entitlement engine binding evidence state to claim-state mutation.

## Adversarial intervention disposition

The originally proposed mutation experiment cannot lawfully be represented as a test of an existing automatic mechanism, because no existing automatic claim-entitlement consumer was located to exercise.

Creating such an engine now and then demonstrating it would prove that Diamond Gate can implement the mechanism; it would not prove that the current system already possessed the mechanism before this boundary.

Therefore the falsification rule applies.

### Intervention A — source mutation

Required: source identity mismatch automatically demotes a qualified claim.

Current-system result: `NOT DEMONSTRATED`.

### Intervention B — reproduction / qualification failure

Required: failed qualification automatically lowers permissible public standing.

Current-system result: `NOT DEMONSTRATED` at the public-claim registry layer, despite extensive fail-closed execution/qualification mechanisms elsewhere.

### Intervention C — adverse evidence

Required: admissible contradictory evidence automatically changes claim status to held/contradicted under a declared evidentiary contract.

Current-system result: `NOT DEMONSTRATED` as an automatic public-state propagation mechanism.

### Intervention D — presentation drift

Required: public artifact/source mismatch prevents continued display of the stronger representation.

Current-system result: `NOT DEMONSTRATED` for the credibility claim registry itself.

### Recovery

Required: restoration must require new admissible evidence and requalification rather than a manual status toggle.

Current-system result: `NOT DEMONSTRATED` at the public-claim layer.

## What survives

The negative result does not erase the earlier findings.

Diamond Gate still demonstrates a distinctive operating practice in which public claims are explicitly scoped, proof levels are declared, historical/current standing is separated, and claims have actually been contracted when supporting public machinery was retired.

What fails is the automatic propagation arrow:

`EVIDENCE CHANGE -/-> MACHINE CLAIM-ENTITLEMENT CHANGE -/-> FORCED PUBLIC REPRESENTATION CHANGE`

for the currently located public credibility system.

## Next material boundary

There are now two lawful routes, and they must not be conflated.

1. **Novelty route:** search older systems specifically for machine-enforced claim entitlement and automatic public contraction. If mature prior art exists, BT4 as a research contribution collapses further.
2. **Construction-and-test route:** build an isolated evidence-to-entitlement engine under a frozen specification, bind it to a non-production research claim, execute the four adversarial interventions, and compare it directly with Stencila. This would establish a new Diamond Gate capability from this point forward; it cannot be backdated into the current-system chronology.

The strongest next empirical route is (1) first, because implementing before completing that prior-art attack risks spending effort constructing a mechanism that is already mature elsewhere.

# H-Earth Rapid Inspection Development Loop v1

Status: BINDING DEVELOPMENT PROCESS
Purpose: preserve the high-cadence, fail-closed workflow that repeatedly produces owner-inspectable immutable H-Earth environments without touching production.

## Core law
Repository state is authority. Each visual layer is developed as an isolated derivative of the last explicitly preserved baseline. Construction, qualification, shell materialization, and owner inspection are separate gates.

## Canonical loop
1. PRESERVE BASELINE
   - Record exact candidate commit/tree, evidence artifacts, and inspection-shell commit.
   - Never replace a preserved baseline merely because a later experiment exists.
2. DEFINE ONE LAYER RESPONSIBILITY
   - State the narrow engineering responsibility before construction.
   - Define what must remain unchanged: geometry, navigation, semantic geography, performance, etc.
3. READ-ONLY FEASIBILITY/COST AUDIT
   - Inspect actual accepted renderer/runtime.
   - Prefer existing architectural precedent.
   - Set hard resource/sample/draw/instance budgets before mutation.
4. CONSTRUCT OFFLINE EVIDENCE FIRST
   - Bake deterministic fields/assets outside runtime where appropriate.
   - Produce exact hashes and receipts.
5. QUALIFY EVIDENCE
   - Fail closed.
   - A green workflow badge is not authority; the receipt/artifact contents are authority.
   - Freeze artifact IDs/digests once qualified.
6. BUILD ISOLATED DERIVATIVE
   - Base from exact preserved commit.
   - Change only the authorized layer.
   - No production mutation.
7. CORRESPONDENCE AUDIT
   - Prove resource creation, sampler/binding, shader/effect use, draw/sample counts, and preserved invariants.
   - Source presence alone is insufficient; verify the effect reaches the runtime path.
8. MATERIALIZE IMMUTABLE INSPECTION SHELL
   - Use preview/h-earth/corridor/.../B/showroom/globe/h-earth/index.html.
   - Use exact immutable commit through rawcdn.githack.com.
   - Add a unique query selector for the candidate layer.
   - Verify index, selector binding, and target renderer exist at that exact commit before giving the owner the URL.
9. OWNER VISUAL INSPECTION
   - Compare against the immediately preceding preserved shell/video.
   - Judge the layer against its assigned responsibility, not against final-world realism.
10. PRESERVE OR HOLD
   - If responsibility passes, record the new layer as preserved and continue.
   - If not, keep the previous baseline authoritative and retain the experiment as evidence.

## Efficiency rules
- Never rebake/requalify a product merely because inspection infrastructure changed.
- Separate product-candidate identity from workflow/infrastructure identity.
- Freeze evidence by artifact ID + digest + internal asset SHA/receipt, not workflow color.
- Reuse the existing B inspection shell and selector mechanism.
- Do not invent hosting/deployment when immutable GitHack serving is sufficient.
- Do not rerun upstream gates after a downstream-only repair.
- Diagnose the exact failed instruction before another run.
- If workflow YAML fails before job creation, repair syntax only.
- Keep construction commits immutable and publication HELD until qualification/correspondence passes.
- Preserve successful layers independently so experimental branches cannot erase them.

## Visual evaluation law
Each stage is judged against its contract:
- semantic material: regional material identity;
- microtexture: within-family multiscale variation;
- microrelief: relief response from existing microstructure;
- mesostructure: physical scale/parallax cues;
- later water/foliage: their own contracts.
Final realism is the aggregate objective, not the pass criterion for every intermediate layer.

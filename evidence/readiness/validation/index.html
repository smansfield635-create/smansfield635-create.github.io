TRL 7 · Evidence Semantics Validation

The evidence is now bound to what it is supposed to prove.

The Software TRL 7 self-assessment is not validated only for JSON shape. Each criterion declares required capabilities and evidence classes, and the fail-closed validator checks that criterion-local evidence satisfies those bindings with immutable identities where required.

Invariant

Implementation is not execution.

Documented test performance must include both an immutable execution record and executable-test evidence. Implementation source by itself cannot satisfy that criterion.

Invariant

Evidence cannot silently change jobs.

Every evidence item carries a criterion-local identity, evidence class and capability. Required capabilities and evidence classes must be covered inside the criterion they support.

Invariant

Historical code is pinned.

Historical implementation and executable-test evidence must resolve through exact 40-character Git commit identities. Execution records must likewise identify exact commits.

Boundary

Semantic binding is not omniscience.

The validator mechanically verifies declared criterion-to-capability-to-evidence relationships. It does not claim machine understanding of arbitrary source-code behavior, independent third-party verification, NASA certification, or defect-free software.

Pass law

PASS ⇒ criterion identified ∧ capability declared ∧ evidence class declared ∧ criterion-local coverage ∧ immutable identity where required ∧ claim boundary preserved

The defect-maturity criterion remains PASS_BOUNDED. The validator explicitly requires the assessment to say that this is not a defect-free claim.

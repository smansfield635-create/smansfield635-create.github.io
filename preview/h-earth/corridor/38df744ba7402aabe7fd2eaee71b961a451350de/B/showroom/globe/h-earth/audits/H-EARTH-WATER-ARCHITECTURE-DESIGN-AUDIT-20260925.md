## Executive finding

The visible water problem is architectural rather than a missing animation constant.

The repository contains a coherent canonical water-state authority and a separate presentation adapter, but the accepted visible WebGL path does not consume that presentation adapter as its water renderer. The visible far ocean is a large triangle mesh generated by `geometry-distant-context.js`, transported through the canonical render package, projected from source shoreline role 2 to GPU role 4, and then shaded by the generic CP2 fallback path.

Consequently the active renderer receives a triangulated surface with per-vertex water color and geometric normals, but does not receive a dedicated continuous-water material semantic.

The screenshot evidence of large, countable polygon/linoleum boundaries is therefore consistent with the active architecture.

## Authority chain verified at frozen control

### 1. Canonical water state

File:
`h-earth-3d/environment/h-earth.water-state.js`

Contract:
`H_EARTH_CANONICAL_WATER_STATE_RUN_7D_v1`

Canonical water classes:

- NO_WATER
- SHORELINE_CONTACT
- SHALLOW_WATER
- NEARSHORE_WATER
- OPEN_WATER

The state authority supplies, among other fields:

- shoreline distance
- shoreline Z
- water class
- flow direction
- wave direction
- wave amplitude
- wave frequency
- foam intensity
- turbidity
- wetness transfer

Defined base wave profiles include:

- SHORELINE_CONTACT: amplitude 0.08, frequency 0.62
- SHALLOW_WATER: amplitude 0.18, frequency 0.50
- NEARSHORE_WATER: amplitude 0.34, frequency 0.40
- OPEN_WATER: amplitude 0.52, frequency 0.30

This layer is not the problem and remains authoritative.

### 2. Canonical shoreline geometry

File:
`render/geometry-shoreline.js`

Contract:
`H_EARTH_FUNCTIONAL_SHORELINE_GEOMETRY_PROVIDER_COASTAL_CONTINUITY_v2`

Bands include:

- FOAM_CONTACT
- SHALLOW_WATER
- NEARSHORE_WATER
- OPEN_WATER

The provider explicitly delegates visible water presentation to the continuous ocean:

`waterPresentationAuthority: CONTINUOUS_OCEAN_ONLY`

and marks its finite water ribbons as non-visible.

Therefore the visible broad ocean is not the shoreline ribbon.

### 3. Visible continuous ocean geometry

File:
`render/geometry-distant-context.js`

The visible ocean is generated by `buildContinuousOceanField()`.

Frozen baseline sampling:

- X core spacing: 40 world units
- Z core spacing: 24 world units

Each grid cell is explicitly triangulated into two triangles.

The provider records the intended authority as:

- ONE_CONTINUOUS_OCEAN_SURFACE
- DISTANCE_FROM_CANONICAL_COAST_CONTINUOUS
- WORLD_SPACE_FIELD_NOT_RADIAL_RINGS
- historical 23923 color anchors preserved
- visible rectangular termination prohibited

The metadata expresses intended continuity, but the geometry remains an ordinary coarse triangle field. Metadata does not hide topology from lighting.

### 4. GPU transport

File:
`render/gpu-upload-views.run8e-r2d.js`

The active GPU upload layer preserves canonical water optical coordinates and explicitly maps:

`source shoreline role 2 -> GPU role 4`

The purpose is recorded as restoration of 23923 coast-distance optics on the active WebGL path.

This transport layer should be preserved during redesign.

### 5. Active CP2 renderer

File:
`render/persistent-live-renderer.run8e-r3c.cp2-round1-1f520809.js`

The shader receives:

- position
- normal
- base color
- material parameters
- material model code
- surface class code
- primitive index
- role code

The fragment shader has a dedicated branch for role 1 and role 2, but the role-4 water path falls through the generic branch.

The generic branch is vegetation-oriented variation.

Therefore the canonical visible water does not have a dedicated active water presentation branch at the GPU semantic boundary.

The final lighting stage also uses role-dependent diffuse/rim/specular coefficients, with the strongest dedicated water specular treatment attached to role 2 rather than the remapped role 4.

## Root-cause model

The active chain is effectively:

canonical water state
-> distant ocean triangle field
-> per-vertex water color
-> source role 2
-> GPU role 4
-> generic CP2 material path
-> geometric normal + interpolated color + generic lighting
-> visible polygon boundaries

This explains why repeated shader-only motion experiments produced moving/shifting surfaces without eliminating the underlying tile perception.

## What failed and what it proves

### PR #4799
Targeted a non-authoritative renderer path.

Finding: renderer-selection/path mismatch.

### PR #4800
Targeted the role-2 branch.

Finding: canonical visible water was transported as role 4, so the change did not govern the visible water.

### PR #4801
Targeted role 4 but used a presentation-only animated normal/color treatment.

Finding: visible water remained structurally polygonal.

### PR #4802
Added multi-scale role-4 normal/specular animation.

Physical result: water read as shifting glass.

Finding: temporal shading alone cannot repair exposed coarse topology/material semantics.

### PR #4803
Increased ocean tessellation aggressively.

Physical result: initialization/presentation failure with no reported shader, link, WebGL, framebuffer, or context-loss error.

Finding: brute-force global tessellation is not an acceptable solution.

### PR #4804
Used canonical water-state wave parameters in the active role-4 path.

Physical result: underlying tile perception remained.

Finding: canonical state wiring is necessary but insufficient.

### PR #4805 / #4806
Irregularized/staggered the existing triangle field.

Physical result: large polygon boundaries remained visible.

Finding: deforming the floor tiles does not stop the viewer from seeing the floor tiles.

## Design conclusion

The next implementation must be treated as a **water presentation architecture**, not another visual effect.

The canonical state, shoreline contract, color authority, world manifold, camera, framebuffer, terrain, meso, vegetation, and navigation should remain frozen.

The redesign boundary should be the active water representation and its GPU presentation semantics.

## Proposed target architecture

### Layer A — preserve canonical water state

Continue consuming `sampleHEarthWaterState(worldX, worldZ)`.

Do not create a second water truth model.

### Layer B — preserve canonical shoreline coordinates

Continue using the canonical shoreline distance and shoreline frame.

The shoreline remains the spatial anchor for water classes, color, foam, and wave direction.

### Layer C — introduce a dedicated GPU water semantic

The visible ocean needs an explicit water presentation role/material contract.

The design must not depend on the generic role-4 vegetation fallback.

The exact internal numeric role value is an implementation detail; the architectural requirement is that water remains semantically identifiable from upload through fragment presentation.

### Layer D — separate macro surface movement from fine water detail

The renderer should use two coupled fields:

1. Macro field:
   - driven by canonical wave direction, amplitude, and frequency
   - capable of modest vertex displacement where existing geometry density supports it
   - used primarily to establish broad wave form and horizon/shore relationship

2. Fine field:
   - analytic world-space normal perturbation in the fragment shader
   - continuous across triangle boundaries
   - multiple directional components
   - temporally coherent
   - does not require global tessellation multiplication

The fine field must not be tied to primitive ID, cell coordinates, or triangle identity.

### Layer E — eliminate topology disclosure

The material must stop using lighting behavior that exposes each triangle as an independent planar face.

The target is not merely irregular triangles.

The target is that adjacent triangles evaluate the same continuous water field in world space, so the eye cannot recover the mesh partition from the shading.

A successful result should make the underlying triangle field visually irrelevant.

### Layer F — retain canonical color authority

Do not replace the 23923 coast-distance color law during the first redesign.

Water color remains derived from canonical shoreline distance.

The first redesign should change **how water is presented**, not silently change its established palette.

### Layer G — foam remains separate

Foam should remain a shoreline phenomenon derived from canonical water-state foam intensity.

Do not use foam as a disguise for the broad-ocean topology problem.

## Construction sequence

### Phase W1 — semantic water renderer carrier

Clean child of frozen control.

One conceptual change:

- establish explicit active water semantic through GPU transport and CP2 shader
- no topology change
- no tessellation change
- no color-law change
- no terrain change

Mechanical gate:

- canonical water reaches explicit water branch
- role projection is internally consistent
- existing world still presents
- no startup regression

Physical gate:

- environment remains unchanged except for water material behavior
- no vegetation/terrain regression

### Phase W2 — continuous analytic water field

Clean child of W1.

One conceptual change:

- implement world-space continuous normal field using canonical wave direction/frequency/amplitude
- time source must be deterministic and tied to render time, not arbitrary primitive/cell identity
- no geometry density increase

Physical gate:

- no countable square/triangle patches
- no shifting-glass appearance
- coherent movement across the entire visible surface

### Phase W3 — controlled macro displacement

Only if W2 demonstrates that shading alone cannot provide the required physical read.

Clean child of W2.

One conceptual change:

- modest vertex displacement from the same canonical field
- no global tessellation explosion
- preserve shoreline boundary vertices or use a boundary attenuation envelope so the coast remains stable

Physical gate:

- broad wave form visible
- shoreline remains anchored
- no mesh silhouette artifacts
- performance remains within accepted baseline

### Phase W4 — depth/class response

Clean child of W3.

One conceptual change:

- spatially vary wave amplitude/frequency and optical response according to canonical water class
- shoreline contact, shallow, nearshore, and open-water behavior become visibly related rather than one uniform ocean shader

Physical gate:

- transition reads as depth-related water
- no artificial bands or material seams

### Phase W5 — foam and secondary detail

Only after the broad surface is accepted.

Clean child of W4.

One conceptual change:

- animate shoreline foam using existing foam-state authority
- add secondary glint/normal detail only if it improves natural water read

Physical gate:

- foam belongs to shore
- open water remains clean
- no decorative noise masking topology

## Explicitly prohibited next moves

Do not:

- increase the entire ocean grid by an order of magnitude
- add random triangle/cell-specific animation
- animate primitive IDs
- use arbitrary per-cell lifecycles
- replace canonical water colors
- change the shoreline contract
- modify terrain/meso/vegetation to make water look better
- create another parallel water truth model
- route water through the generic vegetation branch
- stack multiple failed water candidates
- promote any candidate without physical inspection

## Performance constraint

The failed tessellation experiment demonstrated that global geometry multiplication can exhaust the presentation budget before producing a useful visual result.

Therefore the default detail mechanism should be shader-space continuous fields, with geometry displacement used only where it materially improves macro silhouette.

## Acceptance definition

Water is not accepted merely because it moves.

A physical PASS requires all of:

1. No visible four-corner tile reading.
2. No obvious diagonal triangle boundaries.
3. Continuous motion across neighboring regions.
4. Motion reads as fluid rather than glass-like material shimmer.
5. Canonical shoreline remains stable.
6. Canonical coast-distance color authority remains intact.
7. Terrain/meso/vegetation remain unchanged.
8. Startup and first-frame presentation remain healthy.
9. No material performance regression.
10. Exact immutable URL reproduces the inspected candidate.

Failure of any item returns to the preceding baseline.

## Final architecture decision

**WATER DEFINITION remains CLOSED.**

**WATER PRESENTATION remains OPEN.**

The next code change should therefore be a **dedicated water-renderer semantic carrier**, followed by a continuous world-space analytic field. It should not be another ocean-grid perturbation.

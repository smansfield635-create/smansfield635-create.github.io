Proof Levels

Five different things can be true about a technical claim.

The levels are cumulative in meaning, not automatic badges of superiority. A mechanism can be observable without being enforced; enforced without being benchmarked; benchmarked without being independently validated. Diamond Gate publishes the highest level actually supported.

Level 1Observable

The implementation or live behavior can be inspected.

Level 2Enforced

Executable machinery rejects a prohibited state or operation.

Level 3Tested

Automated qualification or self-tests exercise the mechanism.

Level 4Benchmarked

Quantitative results exist under a defined protocol.

Level 5Externally Validated

Independent customers, evaluators, organizations or market outcomes provide evidence.

Browser-native software construction

Level 1 · Observable

Diamond Gate public products demonstrate repository-owned HTML, CSS and JavaScript, with WebGL/WebGL2 and GLSL used where spatial graphics require them. The practical claim is direct control of the browser product surface without making a commercial builder the required foundation.

Demonstrated Claim

Bounded exact-head execution

Level 3 · Tested

The bounded execution carrier accepts a closed request shape, rejects caller-supplied arbitrary command fields, resolves a registered executable descriptor, validates admitted operation identity and scope, binds execution to exact repository state and verifies source identities and digests before delegated execution.

Executable evidence
  • carrier.v1.mjs
  • registry.v1.json
  • self-test.v1.mjs
What failure does

Invalid or unregistered execution requests are rejected rather than silently widened into arbitrary execution.

Proof state

Enforced in executable code and exercised by repository self-test infrastructure.

Boundary: this is a scoped execution property of admitted repository operations. It does not mean arbitrary software execution is universally impossible.

Demonstrated Claim

Fail-closed Page Excellence qualification

Level 3 · Tested

Page Excellence is implemented as a mandatory qualification boundary rather than a style guide alone. Page operations are checked against active toolchain identity, architecture authority, source identities, implementation findings, runtime conditions and receipt continuity before a passing disposition is accepted.

What failure does

A missing or non-passing required condition blocks qualification instead of being treated as optional documentation.

Proof state

Executable gating plus associated self-test and workflow infrastructure.

Boundary: passing qualification means declared conditions passed. It is not a universal guarantee that a page or application contains no defect.

Demonstrated Claim

Exact governing-state and source-identity binding

Level 2 · Enforced

Governed operation documents carry exact governing state, admitted paths, operation identity, source identities and content digests. The execution carrier verifies those relationships instead of relying on a moving branch name or session memory as authority.

Operation identity, declared scope and the exact source objects a governed continuation is allowed to trust.

Boundary: this is an identity-and-scope enforcement claim inside the repository lifecycle, not a blanket cryptographic-security claim.

Demonstrated Claim

Repository-operation successor packet compiler

Level 3 · Tested

Diamond Gate contains an explicit successor-packet compiler. It takes a predecessor operation and a fresh successor request, performs declared governing-head rebinds, rejects forbidden authority or scope changes, refuses undeclared stale-head bindings and emits a compiled successor packet with a compiler receipt.

Executable evidence
  • successor-packet-compiler.v1.mjs
  • compiler self-test
  • successor protocol
What it compiles

Repository-operation successor packets when governing state advances.

What it refuses

Implicit authority inheritance, scope expansion and undeclared predecessor-state bindings.

Boundary: this is not a general-purpose website compiler. Diamond Gate will not use the narrower implemented compiler as evidence for a broader compiler claim it has not demonstrated.

Demonstrated Claim

Governed continuity and bounded recovery

Level 3 · Tested

The repository includes dedicated machinery for continuity across changing operation state, successor creation, instrument lifecycle and differential continuity. Recovery is structured around preserving valid evidence, distinguishing execution apparatus from product defects, and requiring fresh qualification where authority or governing state has changed.

What this supports

Repository-level continuation without silently treating stale authority or stale qualification as current.

Proof state

Implemented in executable gates and self-test infrastructure.

Boundary: this is not a claim of uninterrupted service availability under every external infrastructure or network failure.

Claims We Deliberately Do Not Make Yet

Precision is part of the product.

The following phrases require evidence Diamond Gate has not yet established publicly. They remain outside the authorized marketing vocabulary until the corresponding benchmark, external validation, threat model or prior-art work exists.

The Standard

Promise → evidence → boundary.

That sequence is the credibility rule across Governance, Build and Awards. The public language can be forceful because each material technical claim is expected to resolve to an inspectable mechanism, a known proof level and a sentence explaining where the claim stops.

04 / 05

Delay

Treat timing as part of the loop, not as decoration.

  1. Measure observation

    Practical
    Treat timing as part of the loop, not as decoration. Explain how a response arriving too late can reverse the value of feedback.
    Engineering
    Treat timing as part of the loop, not as decoration. Measure observation.
    Empirical
    Treat timing as part of the loop, not as decoration. Use timestamps to distinguish prompt response.

  2. Decision

    Practical
    Decision delay is the time the controller spends evaluating an observed return before selecting the next command. It belongs to computation or deliberation after observation, not to movement of the signal between locations.
    Engineering
    Measure decision latency from the instant the required feedback state is available to the controller until the decision function commits a command, preserving queueing, evaluation, and branch-selection time separately.
    Empirical
    Use controller-side timestamps or decision traces that pair feedback availability with command commitment; do not count network propagation or actuator motion as decision time.

  3. Transport

    Practical
    Transport delay is the time a feedback signal spends travelling across the declared return path before it reaches the controller boundary. It concerns propagation through the channel, not the controller's later choice.
    Engineering
    Measure transport latency between declared send and receive boundaries on the feedback channel, including routing, serialization, buffering, and transmission while excluding controller decision processing.
    Empirical
    Use matched send-and-receive timestamps or route traces for the same returned signal to calculate channel delay independently from decision and actuation intervals.

  4. Actuation latency

    Practical
    Treat timing as part of the loop, not as decoration. Explain how a response arriving too late can reverse the value of feedback.
    Engineering
    Treat timing as part of the loop, not as decoration. Actuation latency.
    Empirical
    Treat timing as part of the loop, not as decoration. Use unrelated later change.

Stability

Determine whether the loop dampens, amplifies, or destabilizes change.

  1. Inspect loop gain

    Practical
    Determine whether the loop dampens, amplifies, or destabilizes change. Show whether repeated response settles the system or makes the problem grow.
    Engineering
    Determine whether the loop dampens, amplifies, or destabilizes change. Inspect loop gain.
    Empirical
    Determine whether the loop dampens, amplifies, or destabilizes change. Observe successive states.

  2. Inspect saturation

    Practical
    Determine whether the loop dampens, amplifies, or destabilizes change. Show whether repeated response settles the system or makes the problem grow.
    Engineering
    Determine whether the loop dampens, amplifies, or destabilizes change. Inspect saturation.
    Empirical
    Determine whether the loop dampens, amplifies, or destabilizes change. Observe alternative explanations before calling the path stabilizing or destabilizing.

  3. Inspect oscillation

    Practical
    Oscillation is repeated reversal around a reference or target: the loop pushes past equilibrium, corrects back across it, and continues cycling rather than settling. A single overshoot is not enough.
    Engineering
    Measure sign reversals, period, amplitude, phase, damping ratio, and whether successive peaks shrink, hold, or grow around the reference state.
    Empirical
    Use ordered state and command timestamps showing multiple direction changes around the same reference with enough cycles to separate a recurring mode from one overshoot.

  4. Inspect runaway paths

    Practical
    A runaway path is self-reinforcing divergence: each pass drives the state farther from a safe or intended region without a restoring reversal that brings it back.
    Engineering
    Track error magnitude, loop gain, saturation entry, directional persistence, and the point where corrective authority can no longer arrest divergence.
    Empirical
    Use successive state, command, and bound records showing error or output increasing in the same destabilizing direction across feedback passes. A bounded alternating cycle or isolated spike is not runaway. Claim boundary: Temporal return does not prove a functioning feedback mechanism unless the return path and resulting change are observed.

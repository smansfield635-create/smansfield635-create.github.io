## 1. Purpose

This contract corrects one demonstrated failure class without reopening the frozen Awards concept:

`TECHNICALLY_PRESENT 3D OBJECT != VISUALLY RECOGNIZABLE OBJECT`

The five object identities remain frozen:

1. EXPERIENCE — `MIRRORLAND_WINDOW`
2. WORLD — `H_EARTH_AUDRALIA_WORLD`
3. COHERENCE — `BRAIN`
4. TRUST — `NINE_SUMMITS`
5. ESTATE — `HOUSE_MANOR`

No alternate metaphor search is authorized.

## 2. Proven defects

The prior successor demonstrated two shared-system defects.

### A. Common host compression

A single square host approximately 145–220 px wide, combined with one circular framing treatment, compressed unlike subjects into icon-scale presentations. The circle became an oval under carousel perspective and visually dominated Brain, World, Trust, and Estate.

### B. Source-intent substitution

The previous recognizability verifier inferred visual success from source literals such as camera labels, target occupancy constants, summit count, donor imports, and scale values. Those checks may verify implementation intent or provenance. They do not prove what a rendered viewer can identify.

Therefore:

`SOURCE_LITERAL_CHECK != VISUAL_RECOGNITION_EVIDENCE`

## 3. Noncompensatory recognition law

An object passes only when its actual rendered frame is immediately recognizable with explanatory card copy hidden.

No amount of correct provenance, valid WebGL, correct triangle count, correct state transitions, or metadata can compensate for a failed recognition frame.

If a screenshot requires explanation to identify the intended object, it fails.

## 4. Required viewport evidence

Every object must pass in both standalone and integrated states at all three classes:

- PHONE
- TABLET
- DESKTOP

A pass at one viewport cannot compensate for failure at another.

Each capture must bind:

- exact candidate commit;
- viewport dimensions;
- object identity;
- lifecycle state;
- reduced-motion state where applicable;
- rendered screenshot identity;
- visible-subject bounds relative to the host/card;
- recognition disposition.

## 5. Object-specific recognition contracts

### EXPERIENCE — MIRRORLAND WINDOW

PASS requires:

- an architectural window silhouette readable before labels;
- the same window structure in opaque and clear states;
- clear state visibly reveals Audralia/world context;
- the window is not reduced to an emblem, circle, node graph, or generic stained-glass icon.

Preferred composition: vertical architectural field.

### WORLD — H_EARTH / AUDRALIA WORLD

PASS requires:

- unmistakable environmental space rather than a terrain swatch;
- readable land/water or equivalent geographic relation;
- foreground / midground / background depth;
- horizon, shoreline, atmosphere, terrain, or equivalent estate-native world cues;
- camera/framing that communicates traversable spatial extent.

A single mound, isolated hill, generic globe, or smooth gradient fails.

Preferred composition: wide landscape field.

### COHERENCE — BRAIN

PASS requires:

- human brain recognizable before labels;
- cerebral volume is visually dominant enough to expose anatomical form;
- hemisphere/fissure and major massing remain legible at card scale;
- surface relief is visible enough that qualified anatomy is not reduced to a pink dot;
- camera remains lateral-oblique/inspection-oriented rather than top-down.

Qualified donor geometry remains immutable.

Preferred composition: large anatomical inspection field.

### TRUST — NINE SUMMITS

PASS requires:

- one coherent geological range;
- exactly nine visually separable summit events in the principal silhouette/readable range structure;
- meaningful saddles/valleys between adjacent summits;
- secondary ridges or landforms sufficient to read as geology rather than clay/blob geometry;
- no tooth/spike row;
- no broad two-or-three-hill blob;
- no visually sliced flat base.

Preferred composition: panoramic mountain field.

### ESTATE — HOUSE / MANOR

PASS requires:

- manor/large house recognizable before labels;
- readable facade/wall mass beneath the roof;
- entrance/front-elevation cue or equivalent architectural orientation;
- wings/towers form a coherent hierarchy;
- roof cannot overwhelm the entire silhouette;
- camera gives a useful architectural three-quarter or comparable recognition view;
- facade and roof materials remain sufficiently separated to read structure.

Donor geometry remains immutable.

Preferred composition: wide architectural field.

## 6. Shared Cycle F integration law

Cycle F may share interaction mechanics, lifecycle vocabulary, teardown, one-heavy-runtime discipline, keyboard traversal, and return semantics.

Cycle F may not impose one visual aspect ratio or one icon-scale frame on all subjects.

The active host must preserve object-specific composition classes:

- `WINDOW_VERTICAL`
- `WORLD_LANDSCAPE`
- `BRAIN_INSPECTION`
- `SUMMITS_PANORAMA`
- `MANOR_ARCHITECTURAL`

The former circular/oval framing device is not protected and must not dominate the subject.

Integration is a destructive test:

`STANDALONE_PASS + INTEGRATION_DEGRADES_RECOGNITION = CYCLE_F_FAIL`

Do not repair an independently passing object merely to accommodate a defective shared host.

## 7. Negative controls

The following prior visual states are explicit negative controls and must not be accepted by the successor gate:

- tiny brain inside dominant oval;
- smooth mound/terrain swatch presented as World;
- smooth two-or-three-hill Trust silhouette presented as Nine Summits;
- roof-dominant Manor with unreadable facade/base.

A recognizability system that would pass one of these controls is itself invalid.

## 8. Qualification order

The mandatory order is:

`SOURCE / PROVENANCE CHECK`
`-> STANDALONE RENDER`
`-> PHONE/TABLET/DESKTOP RECOGNITION`
`-> OBJECT-SPECIFIC REPAIR IF NEEDED`
`-> CYCLE F INTEGRATION`
`-> PHONE/TABLET/DESKTOP INTEGRATED RECOGNITION`
`-> NEGATIVE CONTROL REJECTION`
`-> RUNTIME / PERFORMANCE / REDUCED-MOTION / ERROR CHECKS`
`-> COMPLETE VERDICT`

Source-code checks may support provenance and runtime qualification but may never manufacture a visual-recognition pass.

## 9. Evidence and authority boundary

Until real rendered evidence exists, recognition status is `UNEVALUATED` or `FAIL_CLOSED`; never inferred PASS.

This operation creates no merge, deployment, publication, award, or owner-acceptance authority.

A draft review PR is permitted only after the complete candidate gate passes.

## 10. Terminal success condition

Required terminal candidate result:

`5/5 STANDALONE RECOGNITION PASS`
`+ 5/5 INTEGRATED RECOGNITION PASS`
`+ NEGATIVE CONTROLS REJECTED`
`+ ONE ACTIVE HEAVY RUNTIME MAXIMUM`
`+ REDUCED-MOTION EQUIVALENCE`
`+ NO PAGE/COPY/READER/NAVIGATION DRIFT`

Anything less is `FAIL_CLOSED`.

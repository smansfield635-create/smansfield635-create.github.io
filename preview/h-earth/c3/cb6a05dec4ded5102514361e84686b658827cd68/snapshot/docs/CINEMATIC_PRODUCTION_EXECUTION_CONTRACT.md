# Cinematic Production Execution Contract

Status: **OWNER-DIRECTED CONTROLLING PRODUCTION INSTRUCTION**  
Date: 2026-09-05  
Companion issue: #2787

This contract prevents repeated failure to enter the actual video-production toolchain. Diamond Gate has already produced multiple cinematic/video artifacts. Future rooms must not behave as though video production is an unknown capability simply because one repository API cannot itself encode media.

## Governing rule

Before any cinematic/video construction room performs precedent discovery, media scavenging, infrastructure escalation, or creates a production branch, it must perform an **execution-capability preflight across the entire room/tool environment**, not merely the connected GitHub API surface.

Required question:

> **Can this room render frames, encode a master, and commit the resulting binary through the available non-Codespaces tools?**

Do not substitute:

`GITHUB_CONTENTS_API_CANNOT_ENCODE_VIDEO -> VIDEO_PRODUCTION_BLOCKED`

for the correct capability test.

## Mandatory production preflight

For a requested pre-rendered cinematic/video master, check the available execution surface for at least:

- Chromium/Chrome or another approved browser renderer;
- FFmpeg or another approved media encoder;
- Node/Python or an equivalent bounded orchestration runtime when needed;
- local/container filesystem access for transient frames/render products;
- connected GitHub binary-blob/tree/commit capability or an equivalent lawful repository-ingress method.

Tool locations may vary by room. **Probe; do not assume.**

If the required tools are present, the production path is:

`FROZEN STORYBOARD + SOURCE TRUTH -> AVAILABLE RENDERER -> FRAMES/CAPTURE -> FFMPEG/ENCODER -> MASTER MEDIA -> VERIFY MEDIA -> GITHUB BINARY BLOB -> TREE/COMMIT -> BOUNDED BRANCH/PR -> OWNER INSPECTION`

For browser-authored cinematics, the normal implementation is:

`HTML/CSS/JS SOURCE -> CHROMIUM FRAME CAPTURE -> FFMPEG H.264/AAC MASTER -> SHA/DECODE/FAST-START CHECKS -> GITHUB BLOB/TREE/COMMIT`

This is an established direct-production class. It does not require Codespaces and does not require GitHub Actions as agent-execution transport.

## Precedent meaning

Established About, Chapter One, and Compass cinematic precedents prove the governing production pattern. Do not repeatedly reopen precedent after the class has been resolved.

- **About precedent** demonstrates direct bounded cinematic construction without a general infrastructure project.
- **Chapter One precedent** demonstrates delivery of an actual encoded H.264/AAC master with exact media verification and bounded repository scope.
- **Compass precedent** demonstrates proportional qualification and owner inspection for noninteractive cinematic work.

Precedent is a production-method authority, not a reason to perform another multi-hour audit before making the film.

## Anti-stall laws

Once storyboard, source truth, and production class are frozen, a construction room must not:

- search broadly for an old MP4 merely because GitHub's text/content API does not encode video;
- infer that no renderer exists without checking the entire room execution surface;
- request, create, recommend, or wait for Codespaces;
- use GitHub Actions as agent-execution transport unless separately and explicitly authorized;
- restart canonical intake, routing, governance, or precedent review that has already closed;
- rebuild a rejected historical runtime when the target is a pre-rendered master;
- treat destination/product runtimes as playback dependencies when they are only source donors;
- call branch creation or source inspection "film progress";
- claim that a film branch has advanced unless the branch is observably ahead of its base with concrete changed paths or a new committed media blob.

## Progress-truth invariant

The following language is prohibited unless repository state proves it:

- "advanced the film";
- "built the master";
- "candidate produced";
- "implementation complete";
- equivalent completion/progress claims.

Minimum evidence for a production-progress claim:

1. exact branch/base identity;
2. branch ahead-of-base count greater than zero;
3. exact changed paths;
4. when a pre-rendered master is the target, a concrete committed media path/blob identity or an explicitly identified intermediate artifact with the next encoding action underway;
5. no protected-surface mutation outside the admitted scope.

If the branch remains identical to base, the correct status is:

`BRANCH_CREATED / PRODUCT_CONSTRUCTION_NOT_STARTED`

## Stop rule

A room may stop before producing the master only on a **concrete, tested blocker**. The blocker report must name:

- the exact missing capability;
- the exact probe that established it;
- why no already-authorized non-Codespaces method can perform that operation;
- the precise artifact boundary reached.

"No native checkout in the GitHub connector," "GitHub API cannot encode MP4," or "Codespace seems easier" are not sufficient blockers when other room/container tools have not been checked.

## Durable operating law

> **Video production capability is determined by the whole available execution environment, not by one repository connector. Probe the renderer and encoder first. Once the film class is settled, make the film. A branch is not progress; a committed artifact is.**
